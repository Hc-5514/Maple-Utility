# 운영 장애 완료 조건 체크리스트

## 목적

코드 수정, CI 통과, HTTP 응답 성공만으로 장애 해결 완료 판단 금지. 외부 API와 비동기 작업은 최종 상태, 저장 데이터, 사용자 화면까지 검증 대상.

## 수정 요청 템플릿

```text
증상:
기대 결과:
현재 결과:
재현 조건:
영향 범위:
완료 조건:
- [ ] 단위 또는 통합 테스트 통과
- [ ] 실제 외부 API 응답 또는 안전한 고정 Fixture 검증
- [ ] 배포 환경 설정 및 실행 이미지 확인
- [ ] 비동기 작업 최종 상태 확인
- [ ] DB 저장 결과 및 사용자 화면 확인
- [ ] 브라우저 콘솔, 프록시, 애플리케이션 오류 부재 확인
```

## 완료 기준

| 작업 유형 | 접수 성공 기준 | 해결 완료 기준 |
| --- | --- | --- |
| 동기 API | HTTP 2xx 응답 | 응답 계약, DB 변경, 화면 반영 확인 |
| 비동기 API | HTTP 200 또는 202와 작업 ID 수신 | 작업 상태 `COMPLETED`, 완료·건너뜀 합계, DB 및 화면 반영 확인 |
| 외부 API 연동 | 요청 전송 또는 HTTP 2xx | 실제 응답 형식 파싱, 저장 결과, 재시도·오류 처리 확인 |
| 배포 설정 변경 | 환경변수 등록 또는 이미지 배포 | 실행 컨테이너의 환경변수와 이미지 SHA, 실제 사용자 흐름 확인 |

`HTTP 200` 또는 `HTTP 202`는 작업 접수 성공 의미. 비동기 작업의 최종 성공 근거는 `SyncJob` 등 상태 조회 API의 `COMPLETED` 상태.

## 외부 API 검증 절차

1. 공식 문서의 엔드포인트, 요청 파라미터, 응답 스키마 확인
2. 운영과 동일한 권한의 키로 최소 요청 실행
3. 민감정보를 제거한 실제 응답 구조와 코드 DTO·파서 비교
4. 문서와 실제 응답이 다르면 허용 형식, 오류 코드, 회귀 Fixture 추가
5. 실패 시 HTTP 상태, 외부 오류 코드, 내부 오류 코드, 작업 ID 기록

API Key, OAuth 코드·토큰, Refresh Token, 개인정보, 응답 전문은 이슈·PR·로그에 기록 금지.

## 배포 및 운영 검증

1. PR CI와 코드 리뷰 완료
2. 병합 커밋 SHA와 운영 컨테이너 이미지 SHA 일치 확인
3. 필요한 환경변수의 존재와 형식 확인. 값 전문 출력 금지
4. 인증된 실제 계정으로 사용자 흐름 1회 실행
5. 비동기 작업은 최종 상태까지 폴링
6. DB 데이터, 캐시 무효화 결과, 대시보드 표시 확인
7. 브라우저 콘솔, Nginx, 애플리케이션 로그의 신규 오류 확인
8. 동일 흐름 재실행 또는 강제 동기화로 재현성 확인

## 이슈 종료 기록

이슈와 Trouble Shooting 기록에 다음 근거 보관.

- 원인과 수정 커밋 또는 PR 링크
- 테스트 명령과 결과
- 배포 이미지 SHA와 검증 시각
- 비동기 작업 ID와 최종 상태
- DB 및 화면 검증 결과
- 남은 위험과 후속 이슈

## 후속 개선 후보

- 외부 API 호출 감사 로그의 독립 트랜잭션 저장
- 파싱 성공 후 외부 API 응답 캐시 저장
- 작업 상태별 사용자 메시지 및 재시도 안내
- 운영 검증 자동화와 알림 연동
