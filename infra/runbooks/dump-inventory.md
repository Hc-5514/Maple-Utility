# 수동 덤프 내역 관리

수동 덤프(`manual-backup.sh`, `develop-local.sh fetch-backup` 등)의 목적·검증·삭제 판단을 한 곳에 남기는 규칙. 자동 백업(R2 `daily/`·`weekly/`)은 대상 아님.

## 1. 원칙

1. **사실 값은 복제하지 않음.** 시각·SHA-256·행 수의 정본은 각 덤프 디렉터리의 `manifest.txt`·`SHA256SUMS`. 문서에 옮겨 적으면 어긋남
2. **의미만 기록.** 목적, 연관 이슈·작업, 복구 검증 결과, 보관 위치, 삭제 조건·삭제일
3. **내역 파일은 비공개.** `docs_private/덤프 내역.md`(Git 제외). 덤프 내용·시크릿·API Key 값 기재 금지
4. **행은 삭제하지 않음.** 덤프를 지우면 삭제일만 기입해 이력 유지

## 2. 작성 시점

| 시점 | 할 일 |
|---|---|
| 덤프 생성 직후 | 내역 표에 행 추가(목적·연관·보관 위치). 복구 검증 칸은 `미확인` |
| 격리 복구 검증 직후 | 복구 검증 칸에 일시와 결과(행 수 일치 여부) 기입 |
| 덤프 삭제 직후 | 삭제일 기입, 삭제 위치(서버/PC) 명시 |
| 세션·작업 시작 시 | 아래 조회 명령으로 실제 상태와 내역 표를 대조 |

## 3. 사실 조회

```bash
bash infra/scripts/list-backups.sh ~/Maple-Backups               # PC
bash infra/scripts/list-backups.sh ~/maple-manual-backups         # 서버
```

관측 시각·크기·SHA-256 앞 12자·users/characters 행 수·상태 표시. 체크섬 불일치, `.partial` 존재, `manifest.txt` 누락 시 해당 행에 표시하고 종료 코드 1.

## 4. 내역 표 템플릿

`docs_private/덤프 내역.md`에 아래 열 구성을 유지.

```markdown
| 덤프 ID | 목적 | 연관 | 복구 검증 | 보관 위치 | 삭제 조건 · 삭제일 |
|---|---|---|---|---|---|
| `20261106T235433Z-1445334` | 시크릿 교체(0-2) 롤백 지점 | 0-2 체크리스트 | 2026-11-07 격리 컨테이너 전체 복구, 27개 테이블 행 수 일치 | PC `~/Maple-Backups/` | 0-2 전 항목 검증 후 |
```

| 열 | 작성 기준 |
|---|---|
| 덤프 ID | 디렉터리 이름 그대로(`YYYYMMDDTHHMMSSZ-PID`, 접두어 포함) |
| 목적 | 어떤 작업의 롤백 지점인지 한 줄. 추정이면 "추정"과 근거 명시 |
| 연관 | 이슈 번호, 체크리스트, 런북 |
| 복구 검증 | `미확인` 또는 일시·방법·결과. `pg_restore --list` 성공만으로 검증 완료 표기 금지 |
| 보관 위치 | PC/서버 경로 구분. 서버 사본은 PC 사본 체크섬 확인 후 삭제 |
| 삭제 조건 · 삭제일 | 조건이 충족되기 전 삭제 금지. 삭제 후 날짜 기입 |

## 5. 보관 정책

- 롤백 지점은 해당 작업의 최종 복구 검증이 끝나기 전까지 삭제 금지
- 서버 보관 최소화. 덤프에는 암호화된 사용자 API Key가 있으므로 서버 침해 시 `NEXON_API_KEY_SECRET`과 함께 유출될 수 있음
- 보관 위치는 Git·클라우드 동기화 폴더 밖의 암호화된 개인 저장소
- 시크릿 교체 같은 위험 작업은 직전에 새 덤프 생성. 이전 덤프 재사용 금지

## 6. 새 세션 시작 체크

1. `docs_private/덤프 내역.md` 읽기
2. `list-backups.sh`로 실제 상태 대조, 내역에 없는 디렉터리나 삭제일 없이 사라진 행 확인
3. 불일치 시 임의로 정리하지 말고 사용자에게 보고
